## 2. 已通过的核心检查

### Architecture / Authority

无 P0/P1。

审查认可：

- `codebridged` 是唯一持久权威；
- CodeBridge.app 是无持久领域状态的 Native Host Adapter；
- Bridge Kernel 保持无状态；
- Domain Service 各自拥有独立不变量；
- 三类 Authority 边界明确：
  - CodeBridge Lifecycle Journal；
  - Provider-native Conversation Content；
  - Volatile Computer Input Arbitration。

没有发现 god-core 或竞争的持久 Authority。

### Security

无 P0/P1。

审查认可：

- 模型可见路径无法创建/扩大 Grant；
- V1 model-callable `permission_grant` 在 V2 中明确移除；
- Remote Approval Token 只存在于 tool-result `_meta`；
- deny-wins 与权限衰减；
- Computer Grant 受 Lease 限制；
- Host IPC 的 peer UID + Code Signature 校验；
- Same-user / App Compromise / OS TOCTOU 都被作为残余风险显式记录，而不是隐藏。

### Computer Use

无 P0/P1。

当前安全机制通过：

- Frame-cited Input；
- `arbiter_instance`；
- `controller_epoch`；
- `geometry_generation`；
- Checks 1–5 逐事件重新校验；
- Pointer 注入时重新 Hit-test；
- 每个 Key Event 前检查 Focused/Frontmost App；
- 用户物理输入抢占；
- Input Monitor 不可用时 Fail Closed；
- Human Hold 与 Human-only Resume；
- Lock / Screen Saver / Fast User Switching 时 Suspended + 丢弃排队输入。

最后一次 OS 查询到实际 CGEvent Delivery 之间仍可能存在有限系统级竞态；当前文档已将其明确记录为 Residual Race，不构成架构阻断。

### Runtime / Journal

无 P0/P1。

审查认可：

- State + Event 同事务；
- Per-stream 连续 `seq`；
- Global Journal `pos`；
- Restart Recovery → `interrupted`；
- ProviderSession 只允许一个 Active Run；
- Continuation Chain Single Writer；
- 从已验证 V1 RunManager / RunStore / RunEvent 迁移的方案成立。

### Bridge / Tunnel

无 P0/P1。

通过的目标链路：

```text
ChatGPT
  -> Secure MCP Tunnel
  -> tunnel-client
  -> Streamable HTTP MCP over Unix-domain socket
  -> codebridged
```

Caller、Widget/Model 区分、Local MCP 限制和 Journal Cursor 重连模型均自洽。

### CodexBridge 上游复用

无 P0/P1。

审查认可：

- Upstream 不是 Critical Path 依赖；
- 准确 Commit / 原样 Build / Module Audit 属于 Phase 0；
- Package Dependency > Copy with Attribution > Vendored Subtree；
- 拒绝整体 Fork / 架构反转；
- Upstream Type 禁止进入 CodeBridge Domain / Host IPC。

### Orchestration

无 P0/P1。

当前最小抽象足以支持未来：

- OMP；
- Codex；
- OpenCode；
- OpenAI Agents。

CodeBridge 负责：

具体 Multi-agent Protocol 继续由 Provider 自己负责。

## 3. Non-blocking P2

本轮登记以下 P2，但均不阻塞 Freeze：

1. Event Tap 对硬件输入/引擎 CGEvent 的区分，以及 Input Monitoring 与 Accessibility 的具体依赖，后续应专项实测；现有 Fail Closed + E2E 抢占测试足够支持 Freeze。
2. `events_wait` / Widget Long-poll 时长限制尚未验证；属于 Phase 3，且已有替代路径。
3. 当 `openai/widgetSessionId` 不可用时，Approval Token 的绑定会弱一些；当前 once/session-only + opt-in 足以接受，Phase 1 Exit Review 再复核。
4. 审查报告提到 `reattalse` 拼写，但当前工作树已经是 `reattach`，无需修改仓库。
5. Phase 1A 首先实现 Policy 子集，后续再补完整 Scope；这是 Additive，不得把子集误认为最终 Policy Surface。

均不阻塞 Phase 0。
