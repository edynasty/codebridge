## 2. Verified areas

### Architecture and authority

No P0/P1.

The review accepted:

- `codebridged` as the single durable authority;
- CodeBridge.app as a native host adapter with no durable domain state;
- stateless Bridge kernel;
- domain services with separate invariants;
- distinct authorities for:
  - CodeBridge lifecycle journal;
  - provider-native conversation content;
  - volatile Computer input arbitration.

No god-core or competing durable authority was found.

### Security

No P0/P1.

The review accepted:

- no model-visible path can create or widen a Grant;
- V1 model-callable `permission_grant` is explicitly removed from V2;
- remote approval tokens are hidden in tool-result `_meta`;
- deny-wins and permission attenuation;
- Computer grants are lease-bound;
- Host IPC peer UID + code-signature checks;
- residual same-user/App-compromise/OS-TOCTOU risks are documented instead of hidden.

### Computer Use

No P0/P1.

The review accepted the current protections:

- frame-cited input;
- `arbiter_instance`;
- `controller_epoch`;
- `geometry_generation`;
- per-event checks 1–5;
- pointer hit-testing at injection time;
- per-key focused/frontmost-app checks;
- physical user preemption;
- fail-closed input-monitor behavior;
- human hold and human-only Resume;
- lock/screen-saver/fast-user-switch suspension and queued-input discard.

The remaining OS-level interval between the last query and actual CGEvent delivery is treated as an explicit residual race, not an architecture failure.

### Runtime and journal

No P0/P1.

The review accepted:

- state + event in one transaction;
- per-stream contiguous `seq`;
- global journal `pos`;
- restart recovery to `interrupted`;
- ProviderSession single-active-Run rule;
- continuation-chain single-writer rule;
- migration path from the verified V1 RunManager/RunStore/RunEvent implementation.

### Bridge and Tunnel

No P0/P1.

Accepted path:

```text
ChatGPT
  -> Secure MCP Tunnel
  -> tunnel-client
  -> Streamable HTTP MCP over Unix-domain socket
  -> codebridged
```

The review found the caller/Widget distinction, local-MCP restrictions and journal-cursor reconnect model internally consistent.

### CodexBridge upstream reuse

No P0/P1.

The review accepted:

- upstream is not a critical-path dependency;
- exact commit/build/module audit is Phase 0 work;
- package dependency > copy with attribution > vendored subtree;
- whole-app fork/inversion is rejected;
- upstream types cannot cross into CodeBridge Domain or Host IPC.

### Orchestration

No P0/P1.

The current minimum is sufficient for future OMP / Codex / OpenCode / OpenAI Agents integration:

- child Run tree;
- permission attenuation;
- budget enforcement;
- model/provider routing;
- cross-provider correlation.

Provider-native multi-agent protocols remain provider-owned.

### Cloud

No P0/P1 requiring resolution before implementation.

The review accepted the deferred direction:

```text
local Run

 -> new cloud Run
 -> continues_run_id
 -> cloud result as Artifact
 -> explicit local apply
```

No assumption treats Codex Cloud as a generic SSH VM.

## 3. Non-blocking P2 notes

The reviewer recorded these as non-blocking:

1. Event-tap behavior and Input Monitoring vs Accessibility should receive targeted validation; existing fail-closed behavior and E2E preemption test are sufficient for Freeze.
2. `events_wait` / widget long-poll duration limits are not yet validated; this is Phase 3 and has fallbacks.
3. If `openai/widgetSessionId` is unavailable, approval-token binding is weaker; once/session-only opt-in limits make this acceptable for now and it should be rechecked at Phase 1 exit.
4. The review reported a `reattalse` typo, but the current working tree already contains `reattach`; no repository change was required.
5. Phase 1A implements a Policy subset before the full four-scope model; this is additive and must not be mistaken for the terminal Policy surface.

None of these block Phase 0.

## 4. Freeze decision

CodeBridge V2 architecture is approved as the implementation baseline.

Frozen architecture does **not** mean every deferred implementation/API detail is frozen. It means:

- architecture-level decisions in the Decision Register are the baseline;
- a change to a Frozen decision requires new evidence and an explicit architecture amendment;
- Deferred items remain intentionally open until their trigger;
- Phase 0 may refine implementation details but should not redesign the architecture merely for preference.

Next action: begin Phase 0.
